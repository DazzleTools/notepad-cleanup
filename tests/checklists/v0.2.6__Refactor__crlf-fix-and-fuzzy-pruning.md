## What this is

Verification steps a human runs against a real Windows 11 Notepad session to confirm: (1) extracted files are byte-clean CRLF (the pre-v0.2.6 writer doubled every carriage return -- #17); (2) `compare` finishes in seconds instead of minutes with identical match results; (3) near-match output reports the correct session for its canonical path. Automated tests cover the logic; this document covers real-control extraction variance, terminal rendering, and performance feel.

## Prerequisites

1. Windows 11 with Notepad, several tabs open (at least one multi-line tab)
2. notepad-cleanup v0.2.6 installed (`notepad-cleanup --version`)
3. At least one historical session folder in a configured search dir (see `notepad-cleanup config show`)
4. Python 3.10+ on PATH (used for byte-level checks below)
5. **Backup the hash cache** before starting (it sits next to your output folder):

   **cmd.exe**:
   ```cmd
   copy "%USERPROFILE%\Desktop\.notepad-cleanup-dedup-cache.json" "%TEMP%\dedup-cache-backup.json"
   ```
   **PowerShell**:
   ```powershell
   Copy-Item "$env:USERPROFILE\Desktop\.notepad-cleanup-dedup-cache.json" "$env:TEMP\dedup-cache-backup.json"
   ```
   **POSIX**:
   ```bash
   cp ~/Desktop/.notepad-cleanup-dedup-cache.json /tmp/dedup-cache-backup.json
   ```

Reset between sections: extraction tests create new `nc-YYYY-MM-DD__hh-mm-ss` folders on the Desktop -- delete the ones this checklist creates (prefer `dz safedel` if installed) and no other state changes.

## High-Value Verification (~5 minutes)

### HV.1 -- Fresh extraction writes clean CRLF, byte for byte

Validates: the #17 writer fix on a real Notepad control (both the read normalization and the explicit `\r\n` serialization).

- [ ] **Steps** (cross-shell; the check is a Python one-liner):
  1. `notepad-cleanup extract` (accept Phase 2 if prompted)
  2. Note the output folder path, then:
  ```
  python -c "from pathlib import Path; import sys; fs=list(Path(sys.argv[1]).glob('window*/tab*.txt')); bad=[f for f in fs if b'\r\r\n' in f.read_bytes()]; lone=[f for f in fs if (lambda r: r.count(b'\r')!=r.count(b'\r\n'))(f.read_bytes())]; print(len(fs),'files, CRCRLF in',len(bad),', lone CR in',len(lone))" "<output-folder>"
  ```
- [ ] **Expected:** `N files, CRCRLF in 0 , lone CR in 0`
- [ ] **Why this matters:** if this fails, the tool is still munging every note it saves -- the core bug of #17.

### HV.2 -- Round trip matches Notepad's own save exactly

Validates: extraction output == what Notepad itself writes for the same tab.

- [ ] **Steps:**
  1. Pick a multi-line extracted file from HV.1's session; open it in Notepad (double-click)
  2. In Notepad: File > Save As to `%TEMP%\roundtrip.txt` (keep UTF-8)
  3. Compare bytes:

  **cmd.exe**: `fc /b "<extracted-file>" "%TEMP%\roundtrip.txt"`
  **PowerShell**: `fc.exe /b "<extracted-file>" "$env:TEMP\roundtrip.txt"`
  **POSIX**: `cmp "<extracted-file>" /tmp/roundtrip.txt && echo identical`
- [ ] **Expected:** `FC: no differences encountered` / `identical`
- [ ] **Why this matters:** byte-identity is the definition of "not munging user data."

### HV.3 -- compare --last finishes in seconds

Validates: the exact-bounds pruning on a real index.

- [ ] **Steps:** `notepad-cleanup compare --last` against a real history (hundreds of indexed files)
- [ ] **Expected:** the Comparing phase completes in single-digit seconds (previously minutes); progress bar advances visibly rather than stalling per file
- [ ] **Why this matters:** the 247x speedup is the headline of this release; a regression here means the bounds tier is not engaged.

### HV.4 -- Near-match Session line names the canonical's session

Validates: the session_dir fix (was `paths[0]`, misreported ~97% of multi-copy near-matches).

- [ ] **Steps:** in HV.3's output, for each Near-Match entry compare the session folder inside the `~ C:\...\<session>\...` canonical path against the `Session:` line beneath it
- [ ] **Expected:** they name the SAME session folder, on every entry
- [ ] **Why this matters:** provenance reporting -- the old output pointed users at the wrong session for the file it just showed them.

### HV.5 -- Old hash cache is discarded, not trusted

Validates: the cache version gate.

- [ ] **Steps:**
  1. Open `.notepad-cleanup-dedup-cache.json` (Desktop) and confirm it now has the shape `{"version": 2, "files": {...}}`
  2. Replace it with the pre-upgrade backup from Prerequisites (the old flat format), run `notepad-cleanup compare --last` again
- [ ] **Expected:** the run succeeds (re-hashes silently, only slightly slower on the index step) and rewrites the file in the versioned shape
- [ ] **Why this matters:** an old cache holds hashes from old semantics; trusting it would silently corrupt match results.

### HV.6 -- Custom threshold coefficients still work

Validates: env overrides retune both the threshold AND the pruning bounds.

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  set NOTEPAD_CLEANUP_THRESH_C=25.0
  notepad-cleanup compare --last --show-threshold
  set NOTEPAD_CLEANUP_THRESH_C=
  ```
  **PowerShell**:
  ```powershell
  $env:NOTEPAD_CLEANUP_THRESH_C = "25.0"
  notepad-cleanup compare --last --show-threshold
  Remove-Item Env:\NOTEPAD_CLEANUP_THRESH_C
  ```
  **POSIX**:
  ```bash
  NOTEPAD_CLEANUP_THRESH_C=25.0 notepad-cleanup compare --last --show-threshold
  ```
- [ ] **Expected:** thresholds shown are larger than default; near-match count is >= the default run's; still completes in seconds
- [ ] **Why this matters:** the bounds must stay exact under ANY curve, not just the shipped one.

## Section 1: Extraction and writer details

### 1.1 Single-line and empty tabs

- [ ] **Steps:** ensure the Notepad session includes a tab with a one-line note (no Enter presses) and an empty tab; run `notepad-cleanup extract`
- [ ] **Expected:** one-line tab saves with no trailing newline bytes added; empty tab is recorded in `_info.json` with `"content_type": "empty"` and no file
- [ ] **Check:** the one-line file's byte length equals its visible character length (UTF-8 multibyte chars aside)

### 1.2 Tab loaded from a Unix (LF) file

- [ ] **Steps:** create `%TEMP%\lf-test.txt` with LF-only endings (e.g. `python -c "open(r'<path>','wb').write(b'a\nb\nc')"`), open it in Notepad, extract
- [ ] **Expected:** the extracted copy uses CRLF endings (uniform output policy) -- content characters identical, endings normalized
- [ ] **Check:** `python -c "r=open(r'<extracted>','rb').read(); print(r.count(b'\r\n'), r.count(b'\n'))"` -- counts are equal

### 1.3 Manifest char counts

- [ ] **Steps:** open the session's `manifest.json`; pick a multi-line tab and compare its `chars` value to the extracted file
- [ ] **Expected:** `chars` equals the character count WITHOUT carriage returns (file bytes = chars + newline count + multibyte extras)

## Section 2: Compare behavior and display

### 2.1 Progress stages render correctly

- [ ] **Steps:** watch the Comparing progress line during `compare --last` on a history with near-match candidates
- [ ] **Expected:** status shows `vs: <candidate> [chk:N]` with N in 1..5 (5 stages now: length-bound, ratio, size, char-bag, char-diff); no Unicode garbage, no line-wrapping artifacts at normal terminal width
- [ ] **Why:** the stage numbering changed from 4 to 5 steps; docs and display must agree

### 2.2 Results identical across a re-run (cache warm vs cold)

- [ ] **Steps:** run `compare --last` twice; delete `_compare_results.json` from the extraction folder between runs to force recompute
- [ ] **Expected:** identical Results counts and identical match listings both times

### 2.3 Diff script spot-check

- [ ] **Steps:** run the generated `_compare_diffs.cmd` for 2-3 near-match pairs (uses your configured diff tool)
- [ ] **Expected:** the pairs are genuinely near-identical documents; differences shown are small real edits (or phantom blank lines when the old copy predates v0.2.6 -- see docs/archive-repair.md)

## Section 3: Determinism

### 3.1 Canonical stability across runs

- [ ] **Steps:** run `compare --last` twice and compare the canonical paths (`= ...` / `~ ...` lines) between runs
- [ ] **Expected:** byte-identical canonical selections both runs

## Reporting issues found

1. Note the section/step, exact command, and output

3. File an issue referencing this checklist and the commit SHA

## Cleanup

1. Delete session folders created by this checklist (prefer `dz safedel <folder>`)
2. Restore the cache backup only if you want the pre-upgrade state back (not recommended -- the versioned cache regenerates itself):

   **cmd.exe**: `del "%TEMP%\dedup-cache-backup.json"`
   **PowerShell**: `Remove-Item "$env:TEMP\dedup-cache-backup.json"`
   **POSIX**: `rm -f /tmp/dedup-cache-backup.json`
3. Delete `%TEMP%\roundtrip.txt` and `%TEMP%\lf-test.txt` if created
